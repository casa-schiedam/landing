{% comment %} Renders one .schedule-item block for a workshop or event collection item — the single source of the markup used on both workshops.html and events.html, so they can never drift apart. Usage: {% include schedule-item.html item=some_item %} {% include schedule-item.html item=some_item past=true %} `item` is a document from the workshops or events collection (front matter: title, date, time, duration, place, price, seats, tags, book_url, book_label, category, past_note — see _templates/ for the full schema, every field but title/date/book_url is optional). `past=true` renders it in the "already happened" state: the schedule-item--past class, past_note instead of a booking button (or nothing, if past_note isn't set), and no data-date-driven client-side logic will touch it again — see assets/js/site.js, which already skips anything already carrying schedule-item--past. Every field is HTML-escaped on the way out (Raffa is typing these values into a text file — an accidental & or < shouldn't be able to break the page), which is also why this can't just be a straight copy of the old hand-written markup: that used raw ampersands like "Raffa & Vale" without entity-escaping them.
